# Карта данных и воспроизводимость

**Источник:** предоставленный командой локальный ZIP `dataset.txt.zip`, содержащий `dataset.txt`. В публичную версию репозитория **не включён**: происхождение/лицензия и персональные данные ещё требуют проверки. Файл воспроизводится владельцем данных через локальный путь `data/dataset.txt.zip`.

## Формат, классы и очистка

- Исходные строки: **248 290**. После исключения многометочных записей исходным single-label парсером: **239 957** строк; после нормализации и дедупликации: **239 900**.
- Многометочные строки (`INSULT,THREAT`, `INSULT,OBSCENITY` и другие комбинации) — **8 333**: это **не испорченные строки**, а валидные строки, исключённые правилами исходной задачи; риск смещения класса `toxic` и уменьшения покрытия.
- Исходная схема: `NORMAL → neutral`, `INSULT/OBSCENITY → offensive`, `THREAT → toxic`.
- Количество строк после single-label парсинга: neutral **203 685**, offensive **30 812**, toxic **5 460**. Значительный дисбаланс классов объясняет выбор **macro-F1** и **recall toxic**, а не одной accuracy.
- Нормализация: lowercase, `ё → е`, пробелы схлопываются, повторы и конфликтующие тексты исключаются до разбиения.
- Фиксированное разделение: `train=167 930`, `validation=35 985`, `test=35 985`; `random_state=42`, стратификация по классам. Проверяется отсутствие пересечения между train/validation/test.
- Контроль целостности: **SHA-256 распакованного TXT** `426e6bd2514fb974b68c3794da6862f5c67a34f32bdd41efeb5266a101048381` совпадает с `artifacts/baseline_metadata.json`. SHA самого ZIP отличается — его нельзя использовать вместо TXT-хеша.

## Команды проверки

```bash
# С файлами в data/ (локально, НЕ GitHub):
python -m mlops.audit_dataset --data data/dataset.txt.zip
python -m mlops.evaluate_baseline --data data/dataset.txt.zip
```

В `reports/dataset_audit.json` сохранены агрегированные результаты без самих комментариев. В `reports/baseline_real_dataset_evaluation.json` — тестовые метрики и confusion matrix. Отчёт о сопоставлении — [REAL_DATA_EVALUATION_RU.md](REAL_DATA_EVALUATION_RU.md).

## Риски качества, дрейфа и этики

1. **Смещение разметки:** 8 333 многометочных строк исключены; операционное `toxic` здесь соответствует `THREAT`. При реальной модерации текст может одновременно быть оскорбительным и содержать угрозу. *Улучшение:* согласовать и задокументировать multi-label правила; обучить multi-label модель отдельно и оценить на новом независимом test.
2. **Дисбаланс:** toxic — небольшая доля исходных данных; отслеживать recall toxic и per-class precision, показывать матрицу ошибок.
3. **Дрейф:** темы, сленг, новые эвфемизмы, язык сообщений и сезонность меняются. Отслеживать объём, длину текста, источники, классы и confidence, а после появления проверенной разметки — F1/recall по времени; **само распределение предсказаний не является оценкой точности**.
4. **Приватность и возможный вред:** входные комментарии могут содержать персональные данные; в PostgreSQL они сохраняются в поле `text`. Для реального сервиса согласовать законность использования, доступы, сроки хранения и удаление; не публиковать сырые данные и не применять модель для автоматических санкций без участия человека.
5. **Право на данные:** источник/лицензия исходного набора в доступных материалах не подтверждены. Перед публичным размещением датасета требуется установить разрешение на распространение.

**Отдельное ограничение:** опубликованные результаты относятся к исходному holdout, не к независимым пострелизным сообщениям. Нужна ручная контрольная разметка новых примеров.
