# План мониторинга, алертов и реакции

## Что уже реализовано

`app/metrics.py` экспортирует **агрегированные** Prometheus-метрики по `/metrics`:

| Метрика | Что измеряет | Визуализация / зачем |
|---|---|---|
| `up{job="toxicity-api"}` | Успешность сбора метрик / доступность | Grafana API availability (1=UP, 0=DOWN) |
| `toxicity_http_requests_total{route,status}` | Число ответов HTTP | RPS и доля HTTP 5xx по `/predict` |
| `toxicity_http_request_duration_seconds` | Продолжительность HTTP-запроса | p95 HTTP latency (можно добавить график) |
| `toxicity_inference_duration_seconds{source}` | Время вызова модели (Histogram) | p95 inference latency, сек |
| `toxicity_predictions_total{source,predicted_class}` | Успешные прогнозы по источнику и классу | Rate `neutral/offensive/toxic` — **индикатор возможного data drift, а не точность** |

Конфигурации: `monitoring/prometheus/prometheus.yml`, `monitoring/prometheus/alerts.yml`, `monitoring/grafana/dashboards/toxicity-overview.json`. Интервал сбора — 15 сек. Prometheus обращается к `api:8000/metrics` по **внутренней Docker-сети** независимо от внешнего порта хоста.

## Реально заданные алерты (Prometheus rules)

| Алерт | Условие | Что делать |
|---|---|---|
| `ToxicityAPIDown` | `up{job="toxicity-api"} == 0` непрерывно **2 минуты** | `docker compose ps`, `/health/ready`, логи API, состояние БД; восстановить сервис / откатить релиз |
| `ToxicityHighPredictionErrorRate` | Доля HTTP 5xx по `/predict` более **5%** за **5-минутное окно**, удерживается **10 минут** | Разобрать ошибки в логах, оценить БД и артефакт модели, откатить проблемную версию |
| `ToxicityHighPredictionLatency` | p95 инференса более **1 секунды** за **5-минутное окно**, удерживается **10 минут** | Проверить CPU/RAM, размер входа, рост нагрузки, при необходимости ограничить трафик / масштабировать |

**Важно:** правила уже настроены в Prometheus, однако **канал доставки уведомлений (Alertmanager/email/Telegram) ещё не подключён и не проверен**. В учебной локальной демонстрации состояние правил можно смотреть в Prometheus → Alerts, но автоматическое оповещение ответственных не реализовано.

## Данные/модель: план контроля дрейфа и качества

1. **Распределение прогнозов и источников**: сравнивать доли `neutral/offensive/toxic` за день/неделю с согласованным «здоровым» периодом. Для малой выборки (как после 20 тестовых запросов) сигнал неинформативен. Не считать нормой доли обучающего набора: рабочий поток может отличаться.
2. **Длина, язык и формат входных текстов**: в текущем API сбор гистограммы длины и детектора языка **не реализован**. На следующем этапе добавить *агрегированные* гистограммы (без сырого текста, IP, идентификаторов), сравнивать медиану/p95 с эталонным периодом.
3. **Доверие модели**: периодически измерять распределение max probability/confidence по источникам из защищённой БД (не экспортировать пользовательские тексты или IDs). Изменение уверенности — сигнал к расследованию, не доказательство ошибки.
4. **Качество по ground truth**: раз в неделю/месяц проводить ручную разметку репрезентативной случайной выборки (с согласованными правами на данные), рассчитывать macro-F1, `recall toxic`, матрицу ошибок и сравнивать с baseline и предыдущими периодами. До появления меток `true_class` **production-F1 недоступен**.

**Предлагаемое условие для ручного/будущего алерта на дрейф (пока не реализовано):** при минимум **200** новых предсказаниях за **24 часа** доля любого класса отличается от эталонной более чем на **15 процентных пунктов** два дня подряд. Действие — проверить источник трафика, собрать размеченные примеры и сравнить качество. Это **начальный порог для калибровки**, не универсальное правило: его нельзя применять без валидации сезонности и ложных срабатываний. Критические автоматические решения не принимаются.

**Предлагаемое условие для ручной проверки ухудшения модели:** при наличии минимум **100** размеченных новых примеров, если недельный recall(`toxic`) ниже **0,80**, инициировать аудит разметки и сравнение с эталоном. При малом числе примеров toxic оценка статистически нестабильна — нужна проверка доверительных интервалов. Это план, а не действующий Prometheus-алерт.

## Подтверждённое локально

Команда прислала скриншоты Prometheus Target `toxicity-api` со статусом **UP (1/1)** и Grafana: `API availability=1`, показаны requests/sec, p95 inference около **0,00957 с** на тестовых запросах, распределение класса `neutral`. Это подтверждает, что базовые метрики доходят до Grafana, но **не** подтверждает настройку уведомлений, полноценный drift detection или промышленную производительность.
